## PCB 转原理图：一个引脚只允许一条导线（v1.22.1 / 子工具 v1.2.1）

- 现象：一个原理图引脚对应 PCB 封装 4 个焊盘时，同一位置叠画 4 条完全重合的 `WIRE`。
- 根因：`app/pcb-to-sch/wirePlan.js` 的 `planWires` 逐个 `comp.pins` 键出线，而 `comp.pins` 的键是
  **PCB 焊盘编号**（`PAD_NET` 行第 3 字段）。焊盘编号 1~4 是 4 个键，符号侧又是 4 个画在同一坐标的引脚号
  → 同一绝对坐标被画 4 次。（若 4 个焊盘共用同一编号，`comp.pins` 会在解析时就并成 1 个键，不会复现。）
- 修复：`planWires` 每次调用维护 `drawn: Set`，键为 `${x.toFixed(3)}|${y.toFixed(3)}`（只按坐标、不带朝向），
  `pushWireForPin` 判定顺序 = 空网络 → 符号无此引脚号 → 位置已画过。
- 端到端验证脚本（node --input-type=module 直接 import 源码）：PAD_NET 1~4 同网络 + 符号 4 引脚同坐标
  → `WIRE` 1 条 / `LINE` 1 条（修复前 4/4）。
- 测试：`test/pageModels.test.mjs` 新增「一个引脚位置只画一条导线（多焊盘引脚不再叠四条）」，含 V2 与现代
  两种格式 + 反例（引脚坐标不同仍出 2 条，防过度合并）。`npm test` 811 项全绿，`test:samples` 10/10。
- 跨仓：子工具 `PCB转原理图/iframe/js/src/app/pcb-to-sch/wirePlan.js` 逐字节同步，`PcbToSch.js` 产物逐字节一致。

### 踩坑：重建产物会把 About.js / WorkingHours.js 变回未格式化

- 这两个产物在仓库里是 **prettier 格式化过**的（useTabs + 单引号），其余 16 个是 esbuild 原始输出（2 空格 + 双引号）。
  `npm run build:iframe` 只跑 esbuild，直接提交会得到几千行纯格式 diff。
- 处理：`npx prettier --write iframe/js/app/About.js iframe/js/app/WorkingHours.js` 后再看 `git diff --stat`，
  WorkingHours 会回到零差异，About 只剩真正的改动行。**以后重建全量产物都要做这一步。**
- `__APP_VERSION__` 只进了 About.js（`showVersion()` 里 `'v1.22.1'` 是构建期常量），PcbToSch 不含版本号，
  所以两仓 PcbToSch.js 才能保持一致。

## 「创建导线」菜单重构 + 网表缓存（v1.23.0）

- 菜单：`sch` 下原两条 `AutoWirePlacerPCB` / `AutoWirePlacerNET` 收进父项 `CreateWire`（创建导线），
  新增 `UpdateNetlistCacheFromPCB` / `UpdateNetlistCacheFromFile` / `ClearNetlistCache`。
  **「来自PCB」的 registerFn 与实现一行未改**（仍是切 PCB → `pcb_SelectControl.getAllSelectedPrimitives()`）。
- 网表缓存：键 `AUTOWIRE_NETLIST_CACHE`（正文，原样存 .enet 文本，不套 JSON 外层）+ `AUTOWIRE_NETLIST_CACHE_META`
  （来源/时间/文件名/摘要）。**PCB 来源与文件来源共用一个键 → 天然只存一份**，后写覆盖前写。
- **PCB 文档下 `eda.sch_ManufactureData.getNetlistFile('JLCEDA')` 返回的就是整块板的 .enet**（用户确认的），
  不需要选中器件 → 「从PCB更新网表缓存」= 切 PCB → 取文件 → 写缓存 → 切回原理图（切回放 `finally`）。
  切页失败必须整条中止，否则会把原理图自己的网表当 PCB 网表写进缓存（来源造假）。
- `src/js/autoWire/` 现分四层：`index.js`（编排）/ `docSwitch.js`（切页 + `lastSchematicTabId`）/
  `netlistCache.js`（存储）/ `netlistSync.js`（三个菜单动作 + 交互），`netlistParser.js` 加纯函数 `summarizeNetlist()`。
- `summarizeNetlist()` **0 个器件也返回 null**（不只是 JSON 非法时）：既拦坏 JSON，也拦「取错文档 / 空工程」，
  防止把无效网表写进缓存。`switchToPCB()` 改为返回 `boolean`，但 `placeWires('PCB')` 不检查（保持原行为）。
- `deleteExtensionUserConfig` 非所有版本都有 → `clearNetlistCache()` 逐 key try/catch，异常退化为写空串。
- 读文件：先 `Blob.text()`，无此方法再退回 `FileReader`（原 `importNetlistFromFile` 的写法）。Node 环境没有
  `FileReader`，这条兜底让 mock 测试能跑。
- 测试：新增 `test/netlistCache.test.mjs`（11 条），`test/netlistParser.test.mjs` 加 `summarizeNetlist` 5 条；
  `npm test` 827 项全绿。`features.js` 24 → 23 条（两条合并成「创建导线」），README 表格/章节/首页条数同步。
