## PCB 转原理图：一个引脚只允许一条导线（v1.22.1 / 子工具 v1.2.1）

- 现象：一个原理图引脚对应 PCB 封装 4 个焊盘时，同一位置叠画 4 条完全重合的 `WIRE`。
- 根因：`app/pcb-to-sch/wirePlan.js` 的 `planWires` 逐个 `comp.pins` 键出线，而 `comp.pins` 的键是
  **PCB 焊盘编号**（`PAD_NET` 行第 3 字段）。焊盘编号 1~4 是 4 个键，符号侧又是 4 个画在同一坐标的引脚号
  → 同一绝对坐标被画 4 次。（若 4 个焊盘共用同一编号，`comp.pins` 会在解析时就并成 1 个键，不会复现。）
- 修复：`planWires` 每次调用维护 `drawn: Set`，键为 `${x.toFixed(3)}|${y.toFixed(3)}`（只按坐标、不带朝向），
  `pushWireForPin` 判定顺序 = 空网络 → 符号无此引脚号 → 位置已画过。
- 端到端验证脚本（node --input-type=module 直接 import 源码）：PAD_NET 1~4 同网络 + 符号 4 引脚同坐标
  → `WIRE` 1 条 / `LINE` 1 条（修复前 4/4）。
- 测试：`test/pageModels.test.mjs` 新增「一个引脚位置只画一条导线（多焊盘引脚不再叠四条）」，含 V2 与现代
  两种格式 + 反例（引脚坐标不同仍出 2 条，防过度合并）。`npm test` 811 项全绿，`test:samples` 10/10。
- 跨仓：子工具 `PCB转原理图/iframe/js/src/app/pcb-to-sch/wirePlan.js` 逐字节同步，`PcbToSch.js` 产物逐字节一致。

## v1.23.1：五处交互修正（用户逐条反馈）

- **导入图片 DPI 点不动**：`app/import-image/index.js` 的 `dpiValueItems` 选择器写的是 `.dpi-value-item`，
  而 HTML/CSS 用的是 `.ii-dpi-item` → `querySelectorAll` 恒空。后果不止「点了没反应」：`syncDpiUi` 高亮、
  `toggleAspectRatio` 的 `pointerEvents` 也全打在空集合上，只有滑块的 `input` 监听还活着 → 「只能拖滑块」。
  **教训**：这种「一半控件有效一半失效」的现象优先查选择器与 HTML 类名是否对得上。
- **挂机返回提醒从来没生效**（`src/js/WorkingHours.js`）：`idleMs = Date.now() - session.lastMoveTime`
  在「回到活动」那一拍恒为 0（lastMoveTime 刚被 `checkActivity` 重置）→ 永远过不了 `idleThresholdMin`。
  修法：新增 `session.idleSince` + `trackIdle()` 维护挂机起点，`idleMs` 由主循环算好传进 `check()`。
  验证手法可复用：`temp/idle-sim.mjs` 把该文件去掉 logger import 后存成 `.mjs`，用假时钟/假 setInterval/假 eda
  驱动真主循环，对 `git show HEAD:` 的旧版跑同一场景（旧版 toasts=[]，新版 11分4秒）。
- **丝印代码转换**：值列改 `input.cc-value-input`；`shouldModify` 口径从「换算结果不同」改为「框里的值 ≠ 原名」，
  每次 input 重算并同步复选框/全选三态；`applyConversion` 未改（本来就读 `group.value`）。
- **3D 批量更新表头居中**：删 `.nu-table th:nth-child(1~3){left}`，换 `.nu-table thead th{center}`（同特异性、更靠后）。
- **EDA 桥去「调试指令」勾选框**：`debugAllowed()` 恒 true，`commands.js` 门禁保留为防御分支（文案已改）。
- 验证：857 用例全通过；`test/pages/run.mjs` 17/18（WorkingHours 的 drawImage 告警是既有 mock 无布局问题）；
