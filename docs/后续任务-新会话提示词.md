## 任务 2：修好「工时统计」的离线报告（真 bug）

```text
项目：D:/Project/3LCEDA/API/狼黑工具/pro-api-sdk（嘉立创 EDA 专业版插件「狼黑工具」，适配 V3/V4）

先读这几处再动手：
- iframe/js/src/app/working-hours/index.js 第 1090 行 loadLibForInline()、第 1102 行 triggerSecureExport()
- iframe/js/src/app/working-hours/reportTemplate.js（buildLibTags / buildSecureReportHtml）
- scripts/build-iframe.mjs（按页 esbuild 打包的现有逻辑）

要修的问题（已确诊，不用再调研）：
「工时统计」导出报告时想把 echarts 与 fflate 内联进 HTML，实现「发给别人、断网也能看图表」。
但 loadLibForInline() 用的是 fetch('/iframe/js/echarts.min.js')，而宿主把每个 iframe 页面渲染成
blob: 文档（location.href = blob:https://pro.lceda.cn/<uuid>），站内相对/绝对路径一律解析失败。
所以这个 fetch 必然抛错 → 返回空串 → buildLibTags 静默回退 CDN → 断网打开报告图表全空。
这项能力从上线起就没生效过。

目标：导出的 .html 在完全离线（不加载任何 CDN）时能正常解压数据并画出图表。

实现方向（构建期注入，不是运行时读文件）：
1. 在 build-iframe.mjs 里为 working-hours 这个入口加一次 esbuild 的 onLoad 虚拟模块
   （或 define 注入字符串常量），把 iframe/js/echarts.min.js（1.5MB）与 iframe/js/fflate.js（32KB）
   的源码作为字符串编进 bundle。两文件都真实存在，不用下载。
2. 源码侧改成读这个常量，并保留 typeof 保护，让 node 直测环境不报错：
   const LIB_ECHARTS = typeof __WOLF_LIB_ECHARTS__ === 'string' ? __WOLF_LIB_ECHARTS__ : '';
3. 内联前仍要转义 </script（现有代码已有 .replace(/<\/script/gi, '<\\/script')，保留）。
4. buildLibTags 的 CDN 分支不要删——它是兜底，但要在注入成功时走不到。

体积取舍需要先问我：fflate(32KB) 必内联，否则连数据都解不开，没得选；
echarts(1.5MB) 内联会让 WorkingHours 产物从约 108KB 涨到约 1.6MB，这个页面每次打开都要解析它。
请先给两个方案的实际产物体积，再让我决定是否默认内联、还是加 npm run build:iframe --inline-echarts 开关。

验收：
- 断网（或临时把 cdn.jsdelivr.net 指向 127.0.0.1）打开导出的报告，图表能画、数据能解压
- 产物里 grep 不到 cdn.jsdelivr.net
- npm test 全绿（pretest 会跑 check:deps + check:js，基线只允许收紧）

项目硬约束（会踩）：
- 页面产物是单文件 IIFE，HTML 里的行内 onclick 目标必须显式 Object.assign(window, {...})，
  test/inlineHandlers.test.mjs 会扫静态 HTML 与 JS 模板串
- 不要对旧文件整份跑 prettier（工作区 CRLF，.prettierrc 是 useTabs + lf，会产生几千行假 diff）
- 新增/修改的模块必须有五标签模块头（@//module/ @//description/ @//exports/ @//dependencies/ @//example/），
  test/moduleHeader.test.mjs 会核对 @//exports/ 与真实导出逐一对应
- 常用命令：npm run build:iframe（约 1s）、npm test、npm run check:js:update、node test/pages/run.mjs --only WorkingHours
```

## 任务 3：拆「工时统计」的图表层（1736 行 → 目标 600 行内）

```text
项目：D:/Project/3LCEDA/API/狼黑工具/pro-api-sdk（嘉立创 EDA 专业版插件「狼黑工具」，适配 V3/V4）

背景：18 个页面已完成模块化（源码 iframe/js/src/ 下 80+ 个 ESM 模块，产物仍由
npm run build:iframe 按页打包成 iframe/js/app/<Page>.js 的单文件 IIFE）。
唯一没拆完的是 iframe/js/src/app/working-hours/index.js，现 1736 行、6 个 echarts.init()，
承载：总览图、热力图、节律图、周报图、工程管理图的 option 构建 + dataZoom 联动 + 周报渲染。

先做的一件事（不要跳过）：给现状拍快照。
写一个临时脚本（temp/ 下，跑完删），对 6 个 echarts 实例调 getOption()，把结果 JSON 存下来，
作为「拆分前后视觉一致」的比对基准。图表看不出差异但数值差一点，只有这个办法能发现。

拆分目标结构：
- charts/chartView.js：createChartView({ el, theme }) → { init, setOption, resize, destroy, getDataURL, instance }
  统一 init 时机、resize 监听、destroy 清理，消掉 6 份重复的初始化样板
- charts/options/*.js：每个图一个**纯函数** option 工厂，签名统一 (data, theme, opts) => option
  这些必须零 DOM、零 echarts 依赖，能被 node:test 直接 import
- charts/zoomSync.js：linkZoom(views, { sourceId }) 收敛 dataZoom 联动
- index.js 只剩：取数据 → 建 view → setOption → 绑事件 → 刷文本

验收：
- index.js ≤ 600 行
- 每个 option 工厂有单测：给定固定数据，断言 series 数量、yAxis.max、dataZoom 起止等关键字段
- 拆分前后 getOption() 的深度比对一致（容许可解释的差异，并在提交说明里写清）
- npm test 全绿；check:js 里 working-hours 的违规数从 44 降到 ≤10，然后跑 npm run check:js:update 收紧基线
- node test/pages/run.mjs --only WorkingHours 不新增报错（它现在有 canvas 0 尺寸的既有告警，属 mock 缺口，不是回归）

项目硬约束（会踩）：
- 页面产物是单文件 IIFE：凡被 HTML 行内 onclick 引用的函数（当前 13 个 + 表格行里动态生成的
  exportProjectChart / confirmDeleteProject）必须显式挂 window，test/inlineHandlers.test.mjs 会扫
- 不要对旧文件整份跑 prettier（CRLF + useTabs，会产生几千行假 diff）
- 新增模块必须有五标签模块头，test/moduleHeader.test.mjs 核对导出清单
- index.js 里已有一次 Object.assign(window, {...})，别重复添加（历史上重复过两次）
- 常用命令：npm run build:iframe、npm test、node test/pages/run.mjs --only WorkingHours、npm run check:js:update
```

## 任务 4：把 ESLint 存量基线从 109 条降下来

```text
项目：D:/Project/3LCEDA/API/狼黑工具/pro-api-sdk（嘉立创 EDA 专业版插件「狼黑工具」）

背景：v1.19.0 加了复杂度门禁 npm run check:js（config/eslint.iframe.js + tools/check-js.mjs），
规则为 complexity ≤10、max-depth ≤3、max-lines-per-function ≤80、max-lines ≤400。
模块化重构时把原文件的大函数整体搬了过来，所以先用 config/eslint-baseline.json 冻结了 109 条存量，
只拦新增。现在要逐步把它降到 0。

当前分布（按规则）：complexity 63、max-depth 42、max-lines-per-function 4
当前分布（按文件/目录）：
  44  app/working-hours    18  app/generate-net     7  app/create-footprint
   6  app/eda-bridge        5  app/replace-component  4  app/pcb-to-sch
   3  app/netlist-3d        2  app/api-test          2  app/clear-empty-properties
   2  app/code-convert      余下零散

工作方式（一次只动一个文件，每轮独立可回滚）：
1. 先跑 npx eslint --no-eslintrc --config config/eslint.iframe.js -f json "iframe/js/src/**/*.js"，
   把目标文件的违规逐条列出来（规则 + 函数名 + 行号）
2. 拆之前先补测试锁行为。generate-net / pcb-to-sch / replace-component 是写盘类页面，
   test/generateNetSamples.test.mjs 已用真实 V2/V3/V4 样本做解析回归，改完必须跑 npm run test:samples
3. 降复杂度优先用这三招，而不是硬拆：
   - 长 if/else-if 链 → 分派表（项目里已有 CREATORS / TYPE_PARSERS / WRITERS 的先例）
   - 深嵌套 → 早返回（guard clause），把 !cond 的提前 return 提到函数头
   - 巨型函数 → 按「阶段」切（读数据 / 算 / 写 / 报错），阶段之间的中间值显式传参
4. 每降完一个文件跑 npm test，再跑 npm run check:js:update 收紧基线，并记下 before/after 条数

红线：
- 不许为了过 lint 改行为。写盘路径（源码行改写、坐标、属性覆盖顺序）一个字节都不能变
- geometry / sourceParser 是 GenerateNet 的算法核心，改动前必须确认 test/generateNetSamples.test.mjs 全绿
- 不要用 eslint-disable 消违规，除非是有注释说明理由的误报（现有 require-atomic-updates 就是这种情况，已全局关）

验收：config/eslint-baseline.json 的 counts 为空，npm run check:js 无「基线外违规」，npm test 与 test:samples 全绿。

项目硬约束：
- 模块头五标签由 test/moduleHeader.test.mjs 强制
- 行内 onclick 目标必须挂 window，test/inlineHandlers.test.mjs 双重扫描
- 不要对旧文件整份跑 prettier（CRLF + useTabs + lf）
```
