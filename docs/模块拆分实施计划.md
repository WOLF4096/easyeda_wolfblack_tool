# iframe/js 模块化拆分 —— 完整实施计划（待确认，未动手）

> 状态：**计划稿**。本轮不修改任何业务代码，仅产出计划与备份方案。
> 范围：`iframe/js/app/*.js`（18 个）+ `iframe/js/common.js` + 18 个 HTML 的入口标签 + 测试与工具链。
> 规模基线：18 个页面脚本共 12 937 行，加 `common.js` 共 **13 455 行 / 124 个测试用例全绿**。

## 0. 总策略：一次只搬一个页面，公共件先冻结再镜像

三条约束决定了实施顺序必须这样排：

1. **18 个页面各自独立**：每个 HTML 只加载 `common.js` + 自己那一个脚本，彼此零引用。→ 页面迁移可以一页一页做，一页一个可回滚单元。
2. **`common.js` 被全部 18 页依赖**：不能直接把它改成 ESM（会一次性炸掉所有页面）。→ 采用项目已有的「镜像 + 一致性测试」手法：先平行新增 `core/*` ESM 模块，`common.js` 冻结不动，用测试守住两份行为一致；逐页迁移完成后最后删门面。
3. **宿主是 EDA 内部 iframe**，脚本加载方式未经验证。→ 第 0 批先做一个探针页验证模块通道，**不通过就换通道，不进入拆分**。

## 2. 第 0 批（决策门）：已完成 —— 结论是通道 B

**结论：原生 ESM（`<script type="module">` + `import './x.js'`）在本宿主里不可行，走通道 B（esbuild 按页打包）。**

### 2.0 宿主加载机制（实测，2026-10-22，EDA V2.2 客户端）

E2E 探针（`tools/eda-bridge/probes/11~13-module-probe*.js`，经 EDA 桥在扩展页面上下文执行）得到的事实：

| 事实 | 证据 |
|---|---|
| **扩展页面是 `blob:` 文档**，不是文件 URL | `location.href = blob:https://pro.lceda.cn/<uuid>`，`document.baseURI` 同值，无 `<base>` 标签 |
| **每个 `<script src>` 都被宿主改写成独立的无 MIME `blob:` URL** | `document.querySelector('script[src]').src = blob:https://pro.lceda.cn/<另一个 uuid>`（结尾无 `.js`） |
| 宿主**不通过 https 提供**扩展文件 | `GET https://pro.lceda.cn/iframe/js/common.js` → **404**（返回 IDE 的 SPA 兜底 HTML） |
| 渲染器本身支持 ESM | `import('data:text/javascript,export const ok=1')` → 成功；顶层 await 也正常（`v=42`） |
| blob + 正确 MIME 的模块可 import | `import(blobUrl /* type: text/javascript */)` → 成功 |
| **宿主给的 blob 没有 MIME** → 模块被拒 | `import(blobUrl /* 无 type */)` → `Failed to fetch dynamically imported module` |
| **blob 基址不是分层 URL → 相对 import 一律失败** | `blob` 内 `import './dep.js'` → `Failed to resolve module specifier "./dep.js". Invalid relative url or base scheme isn't hierarchical` |
| 相对/绝对路径 `fetch` 也解析不了 | `fetch('/iframe/js/common.js')` → `Failed to parse URL` |

**两个独立死因**：① 脚本 blob 无 JS MIME；② `blob:` 基址无法做相对解析。二者都在宿主侧，插件无法改变。

> ⚠️ **副产物发现（产品 bug）**：`WorkingHours.js:1222` 的 `loadLibForInline()` 用 `fetch('/iframe/js/echarts.min.js')` 试图内联本地库以实现**离线可看**的报告——在这个宿主里它**必然抛错并静默回退 CDN**（`catch` 返回 `''`）。也就是说「离线打开导出报告」这项能力实际上从未生效。修复方式：构建期把库源码作为字符串常量打进 bundle（esbuild `loader: { '.txt': 'text' }` 或生成 `lib-sources.js`），而不是运行时 fetch。**已单独记录，不在本次拆分范围内。**

### 2.1 为什么通道 B 反而更好

| 维度 | 通道 A（原生 ESM，已否决） | **通道 B（esbuild 按页打包）** |
|---|---|---|
| 源码写法 | ESM | **ESM（完全相同）** |
| 运行产物 | N 个模块文件 | 每页 1 个自包含 IIFE（与今天形态一致，宿主照样内联成 blob） |
| HTML 改动 | 18 处 `<script type="module">` | **0 处**（路径不变） |
| 构建步骤 | 无 | 新增 `npm run build:iframe`（约 1s） |
| `node --test` 直接 import 源码 | 可以 | **可以**（node 自动把带 import/export 的 `.js` 识别为 ESM） |
| 体积 | 略小 | 共享模块在多个 bundle 中被 tree-shake 后重复，但每页只带实际用到的部分（估 +150KB 未压缩，zip 后增量更小） |

结论：通道 B 在「源码结构、模块边界、可测性」上与通道 A 完全一致，只是多一个打包步骤——**计划第 3~9 节不受影响**。

### 3.2 命名与分层规则

| 规则 | 内容 |
|---|---|
| 文件命名 | **kebab-case，按功能命名**，不用页面名、不用原文件名；聚合入口固定 `index.js` |
| 禁止 | `export default`（统一具名导出，便于静态分析与 tree-shaking） |
| 依赖方向 | `app/** → pcb|sch|format|project → ui → core`；**反向禁止**；`core/**` 不得 import 任何上层 |
| 同层横向 | 除 `pcb → sch`（发射器复用）外不允许；`ui` 之间不互相 import |
| 循环依赖 | 0 容忍，`npm run check:deps` 静态校验 |
| 单文件规模 | 目标 ≤200 行，硬上限 300 行；单函数 ≤80 行 |
| 页面入口 | `app/<page>/index.js` 只做编排：绑定事件 → 取数据 → 调域模块 → 更新视图，**不写算法** |

> 预计产出 **≈91 个文件**（平均 ~148 行/文件）。其中 `<60` 行的碎文件（`netNamer`、`layerStack`、`padReader`、`sortKey` 等）可按需并回同域邻居；计划按「功能独立」优先，不按行数凑。

## 6. 单文件交付标准（DoD）

### 6.1 模块头（严格按此格式）

```js
/**
 * @//module/ core/length
 * @//description/ 长度单位换算与 API 数值规整（mil/mm 互换、toFixed 结果回成 number）
 * @//exports/ toApiLength, mmToMil, milToMm, readLength, writeLength
 * @//dependencies/ core/util
 * @//example/ const { toApiLength } = await import('./core/length.js')
 *            pcb_PrimitiveObject.create(layer, x, y, src, toApiLength(w, 2), toApiLength(h, 2))
 */
```

规则：
- 五个标签**齐全且顺序固定**；`@//exports/` 必须与真实导出逐一对应（由 `check:js` 校验）。
- `@//dependencies/` 列**模块路径**（非函数名）；无依赖写 `无`。
- `@//example/` 必须是能跑的最小片段（不含省略号）。
- 标签块之后允许一段自由说明，用来放**平台约束/坑**（如「必须先删后建」「V4 会丢 POURED 行」），不新增标签。
- 页面入口（`app/<page>/index.js`）在 `@//description/` 里写清「本页做哪一步、依赖哪些域模块」。

### 6.2 导出函数的 JSDoc

```js
/**
 * 把长度规整成宿主 API 接受的 number
 *
 * @param {number|string} value 原始长度（mil）
 * @param {number} [digits=2] 保留小数位
 * @returns {number} 规整后的数值；入参无法解析时返回 NaN，调用方须自行校验
 * @sideEffects 无（纯函数）
 * @example toApiLength('2275.00') // 2275
 */
export function toApiLength(value, digits = 2) { ... }
```

**强制项**：`@param`（含类型与单位）、`@returns`、`@sideEffects`。
`@sideEffects` 只允许写这几类（本项目的 bug 高发区就是「看着纯其实写了 DOM」）：

| 取值 | 含义 |
|---|---|
| `无（纯函数）` | 不碰 DOM / eda / 存储 / 网络 |
| `DOM` | 读写页面元素 |
| `eda API` | 调宿主 API（列出具体命名空间，如 `eda.pcb_PrimitivePad`） |
| `存储` | `sys_Storage` / `sys_FileManager` 读写 |
| `网络` | WebSocket / fetch |
| 组合 | 如 `eda API（sys_FileManager.setDocumentSource）、DOM` |

`@throws` 只在真的抛异常时写。

### 6.3 复杂度与分支

| 指标 | 上限 | 落地手段 |
|---|---|---|
| 圈复杂度 | ≤10 | `eslint complexity`（仅对 `iframe/js/**`） |
| 嵌套深度 | ≤3 | `max-depth` |
| 单函数行数 | ≤80 | `max-lines-per-function` |
| 单文件行数 | ≤300 | `max-lines` |
| `switch`/`if` 分支 | **>3 必须改映射表或策略对象** | 见 §7 |

### 6.4 导出纪律

- 只导出「跨文件要用」的函数；`.js` 内私有函数**不导出**。
- 不用 `export default`；不用 `export *`（除 `app/<page>/index.js` 的聚合不涉及）。
- 页面入口只导出 `init()`（+ 需要被 HTML 或测试调用的少量函数）。
- 不在模块顶层执行副作用（除 `common.js` 门面它本身就是副作用入口）。

### 6.5 可复用性判据（拆完能验收）

一个模块算「可复用」需同时满足：
1. 不 import `app/**`；
2. 不读 `document`（`ui/*` 例外，但必须由参数注入元素）；
3. 纯逻辑模块能在 `node --test` 里被直接 `import`（无需 mock `eda`）；
4. 至少有一个真实调用方，或有一个单测（避免「搬出来就没人用」）。
