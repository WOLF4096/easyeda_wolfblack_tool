## 五、还需要打磨的地方（按 ROI 排序，均带证据）

### P0 · 结构债，越拖越贵

**5.1 `PcbToSch.buildSchSource` —— 532 行的单函数**（`iframe/js/app/PcbToSch.js:926-1457`）
一个函数里同时做：符号布局、引脚/网络补全、字符串拼装 V2/V3 两套源码、容错。任何一处格式微调都要在 500 行里找落点。
> **改法**：按「数据准备（part/pin/net）→ 布局（坐标/旋转）→ 发射（V2 行 / V3 行）」三刀切开，发射部分与 `autoWire` 共用（见 5.7）。目标：单函数 ≤ 120 行。

**5.2 `GenerateNet` 里三个巨型函数**（`writeChanges:1243` 361 行 / `generateOperations:832` 223 行 / `parseV3Primitives:512` 222 行）
整个文件 1,665 行、22 个顶层函数，几何/解析/UI/写入全在一个 IIFE 里。
> **改法**：拆 `generateNet/geometry.js`（当前 28~343 行的纯几何：`distToSegmentSquared`、`segmentsIntersect`、`getRotatedRectVertices`、`areLayersConnected` 等 12 个函数，约 290 行）、`parsing.js`（`parseV2/V3Primitives`）、`clustering.js`（`UnionFind` + `addToGrid` + `computeClustersFromPrimitives`）。这三块都是**纯计算**，拆出来即可单测——目前它们一行测试都没有。

**5.3 `WorkingHours` 前端（2,187 JS + 1,177 HTML）**
21 处 `innerHTML`（全项目最多）、`renderRhythmChart` 169 行、导出模板里还有一份内联 `escapeHtml`。
> **改法**：先按「数据层（读/聚合 storage）/ 渲染层（表格、图表）/ 导出层（模板）」切；`innerHTML` 收敛到 3~5 个 render 函数里统一走 `WolfCommon.escapeHtml`。

**5.4 统一日志出口**：`console.*` 共 **203** 处，Top：`ReplaceComponent` 36、`autoWire` 17、`PcbToSch` 17（合计 70 处 = 34%）。
其中 `console.log(rawComponents)`、`console.log(jsonData)` 这类整对象打印在大工程下会明显拖慢控制台。
> **改法**：`common.js` 加 `logger`（`debug/info/warn/error` + `WolfCommon.setDebug(bool)`），生产构建默认只出 `warn/error`；先清 Top3。

**5.5 21 处空 `catch {}`**：`ReplaceComponent` 5、`GenerateNet` 5、`EDABridge` 4、`WorkingHours`（前 2 + 后 3）、`CreateFootprint` 2。
`EDABridge` 那 4 处（`:24 :325 :370 :381`）属于"整块功能失败但界面无提示"——用户只会看到"点了没反应"。
> **改法**：至少 `logger.warn(err)`；用户可感知路径补 `sys_Message.showToastMessage`。

**5.6 `common.js` 是 12 个页面的硬依赖**：12 个页面顶层 `const { … } = window.WolfCommon;`，只有 1 处做了 `WolfCommon || {}` 兜底。旧缓存/路径变更 → 12 个页面同时白屏且无任何提示。
> **改法**：统一 `const WC = window.WolfCommon || {};` + 缺模块时页面上给出"公共模块加载失败，请重装扩展"。

### P1 · 明确缺陷或风险

**5.7 源码发射有两份实现**：`PcbToSch.js` 与 `src/js/autoWire/index.js` 各写一套 `["WIRE",…]`（V2）/ `{"type":"WIRE",…}`（V3/V4）。任一处 `maxId`/`ticket`/行尾 `|` 规则漂移，就会出现"某版本写不进去"。
> **改法**：抽 `src/js/common/sourceEmitter.js`（纯函数，可单测），两边共用；`wireChain.js` 已经证明这个模式可行。

**5.8 `PcbToSch` 写入没有 `documentType` 门禁**（`:465` 直接 `setDocumentSource`）
与本次修掉的 `autoWire` 属同一类问题：iframe 打开后用户切到别的文档再点"写入"，就会把原理图源码写进 PCB（平台会拒绝，但提示只有"写入失败"）。
> **改法**：写入前 `getCurrentDocumentInfo()` 判 `documentType === 1`，不匹配时明确提示"请切换到原理图后再写入"。

**5.9 7 处 `alert()` 与宿主 UI 割裂**：`OutPinNet` 4（`:224 :260 :316 :324`）、`NetlistUpdate3DModels` 2、`ClearEmptyProperties` 1。
> `alert` 会阻塞 iframe 且样式与 EDA 主题不一致，统一换 `showToastMessage`。

**5.10 `common.js:getNetlist` 没有空值判定**（`:245`、`:251`、`:259`、`:263`）
`pcb/sch_ManufactureData.getNetlistFile()` 在"当前文档没有网表"时返回 `undefined`，代码直接 `file.text()` → `TypeError: Cannot read properties of undefined`，最终提示是"网表读取失败"，看不出真实原因。
> **改法**：`if (!file) throw new Error('当前文档没有网表，请先生成网表')`。

**5.11 APITest 校准值没有范围校验**：「圆弧角度」这一项已经不再参与计算（v1.17.7 起角度一律按角度制透传），但页面仍显示、仍持久化 —— 现网客户端里就存着 `0.017453`。用户会以为它生效。
> **改法**：删掉该项 UI 与默认值；其余倍率加范围校验（如 `0.1 ≤ k ≤ 10`），越界时提示并不写入。

**5.12 `EDABridge.js` 3 处 `create` 未 `await`**（`:78 :81 :94`）：`count++` 恒成立，异步失败既不进 `errors` 也无法回滚，`import` 指令会"报成功但什么都没建"。

**5.13 创建封装的拦截是对的，但提示文案错了**（`CreateFootprint.js:17`）
本次实测：V4 里 `getFootprintFileByFootprintUuid(uuid, libUuid)` 返回的是 **`ProLib_pc_2026-10-21.elibu` 的 ZIP 包**（3,074 字节，PK 头），**不是可写的源码文本**；`getDocumentFootprintSources()` 只有在封装文档打开时才返回内容；V2.2 下同一个 API 直接返回 `undefined`。
→ 所以"V3/V4 不支持"是准确的，但要改文案：V4 用户看到"此功能暂时不支持 **V3** 版本"会以为自己装错了版本。建议写成"该功能依赖封装源码写入 API，当前版本（V3/V4）尚不支持"。
