## 一、结论摘要

| **工程成熟度** | **85 / 100**（上一版 72，**+13**） |
| **功能均分（25 项）** | **81 / 100**（上一版 75，+6） |
| **发布就绪度** | **80 / 100**（2026-10-22 复核后更新，原为 68：三条写盘流程已人工验证、发布文档已补齐） |
| 测试 | `npm test` **750 / 750 通过**（上一版 108） |

**一句话结论**：**代码已经是"能交付的产品级工程"，但发布流程还是"个人项目级"。**
两天重构把最贵的债（3 个千行文件、7 个超长函数、两份重复发射器、零前端测试）基本还清，
工程分从"及格偏上"跳到"良好偏优"；但**距离正式 GA 缺的不是代码质量，而是四件产品化的事**：
V4 实机回归矩阵、写盘功能的自动备份/回滚、发布文档与隐私说明、CI + 崩溃可观测。

**投入产出最高的 3 件事**（合计约 1.5 天，可把发布就绪度从 80 拉到 90+）：

1. **给 4 个写盘功能加"操作前自动落盘快照"**（1 天）——配合已存在的 V4 丢 `POURED` 问题，这是唯一的用户数据保险；
2. **接 GitHub Actions**（半天）——`npm test` + `test:samples` + `build` 本地跑一遍只要 30 秒，成本极低；
3. **补齐 3 条写盘流程的 V4 人工点按验证** —— **已完成**（2026-10-22，V4.1.78，见 `docs/V4回归记录.md`）。

### 3.1 为什么"发布就绪度"只有 68

综合分衡量**代码好不好**；发布就绪度衡量**敢不敢让陌生人在正式工程上用**。后者额外扣了 5 块：

| 扣分项 | 扣分 | 说明 |
| :--- | :-: | :--- |
| 关键写盘流程未在 V4 实机点按验证 | −10 | 桥能读写源码但点不了按钮，3 条流程只能人工确认 |
| 无自动备份/回滚（仅免责声明） | −8 | V4 丢 `POURED` 是已知未解问题，用户可能丢铜皮 |
| 发布文档未覆盖 V4 | −6 | README 功能表、安装说明仍写 "V2.2/V3"，无 V4 安装路径 |
| 无 CI / 无崩溃可观测 | −5 | 回归全靠开发者本地自律；线上问题只能靠用户口述 |
| 功能缺口未在 UI 显式标注 | −3 | `创建封装` 在 V3/V4 直接不可用，提示文案仍写"只支持 V2.2.45" |

```
85 − 10 − 8 − 6 − 5 − 3 + 15(已有工程基础折算)  ← 折算说明见 §6
= 68
```

> 换算口径：以工程分 85 为基线，按上表扣 32 分，再对"已有三道门禁 + 真实样本回归 + 写盘逐字节验证"给 15 分加分（这些本属 GA 必备，本项目已提前做到）。

## 六、现在是什么水平

### 6.1 横向对标

| 维度 | 本项目 | 典型个人 EDA 插件 | 商业 EDA 插件团队 |
| :--- | :--- | :--- | :--- |
| 代码组织 | 108 模块四层 + 依赖门禁 | 单文件 / 复制粘贴 | 分层 + 依赖注入 |
| 复杂度约束 | ESLint 硬 0（复杂度/嵌套/行长） | 无 | 有，但常带存量豁免 |
| 自动化测试 | 750 用例 + 真实样本回归 | 无 | 有，含 CI 与覆盖率门槛 |
| 写盘正确性验证 | 逐字节对照 + 快照比对 | 手点 | 有 |
| CI / CD | **无** | 无 | 有 |
| 崩溃可观测 | **无** | 无 | 有 |
| 用户文档 / 隐私说明 | 有内置帮助，**缺 V4 矩阵与隐私条款** | 无 | 有 |
| 数据安全兜底 | 有内存回滚，**无自动备份** | 无 | 有 |

**结论分三句**：

1. **代码工程水平：中小型商业团队的合格线以上。** 108 模块、三道门禁、40% 带 `@sideEffects` 的注释、写盘路径逐字节对照 —— 这套做法在 EDA 插件生态里属于前 5%，很多收费插件达不到。
2. **产品化水平：公开 Beta。** 功能广度（22 项）已经超过多数同类插件，但"出错时用户能不能自己恢复""新版本客户端上还能不能用"这两件事还没有制度化答案。
3. **不是"能不能发布"的问题，是"发布给谁"的问题**：给熟悉的群友灰度 → 现在就能发；上架扩展市场面向陌生付费场景 → 还差约 2 周。

### 6.2 一句话定性

> **这是一个"工程纪律已达标、交付纪律未达标"的插件。**

## 七、距离正式发布还差什么

按"卡不卡发布"排序，每条都带**验收标准**。

### P0 · 不解决就不要 GA（约 2 天）

#### 7.1 三条写盘流程在 V4 的实机点按验证 —— 已完成（2026-10-22）

**证据**：`docs/重构汇报-20261021-22.md` §六 明确留了 3 条；桥只能读写源码，点不了按钮。
**风险**：V4 的行为差异（器件两处引用、`Fill` 类型、`createComplexPolygon`）全部是靠桥"写源码 + 重开读数"验证的，
**按钮流程本身**（选器件 → 取库 → 放置 → 删临时件 → 刷新）没有一次端到端确认。

| 流程 | 验什么 | 通过标准 |
| :--- | :--- | :--- |
| 从 PCB 转原理图 | 写入后重开，数符号与引脚 | 符号数 = PCB 器件数 × 部件数，引脚无丢失，坐标不漂移 |
| 生成物理网络 | 网表 / 源码 / 混合 三种写回各一次 | 三种模式下网络数与预期一致；重开文档后弧线导线仍在 |
| 批量替换器件 | 替换后重开，看器件是否真的换了 | `component.uuid` 指向新器件；原坐标/角度不变；库中无临时件残留 |

**验收**：三条各跑 2 个真实工程（1 小 1 大），结果写进 `docs/V4回归记录.md` 并附截图。

#### 7.2 写盘功能的自动备份 / 回滚

**证据**：全项目 `grep 备份` 只命中 README 免责声明与工时数据导出；写盘类只有**内存级**回滚（进程内失败才生效），
关窗或成功写入后的错误无法恢复。而 V4 的 `setDocumentSource` 整份写回**会丢 `POURED` 行**（45,557 → 43,119 字节），
用户表现是"铜皮没了"，只能重算——这不是所有人都知道怎么救。

**至少要做的**：4 个整份/批量写盘功能（生成物理网络、从 PCB 转原理图、批量替换器件、从 PCB 创建导线）
在**执行前**把当前网表或源码原样落到用户可访问的位置（`sys_FileManager` 写临时文件 + toast 给出路径），
并在 UI 上写一句"已备份到 xxx，可随时还原"。

**验收**：故意在写入中途关窗 / 制造异常，用户能凭备份文件在 3 步内还原；备份文件名含时间戳与工程名，不覆盖旧备份。

#### 7.3 `创建封装` 的功能缺口显式化

**证据**：`create-footprint/index.js:28` 提示"此功能只支持 EDA V2.2.45 版本"；
而 V2.2 已停止维护，等于**这个功能实际已死**，但菜单仍然挂在 PCB 菜单里，V4 用户点了只看到一句让人困惑的话。

**二选一（建议前者）**：
- 在 `extension.json` 里按版本条件隐藏该菜单项；或
- 提示改写为"该功能依赖封装源码写入 API，V3/V4 客户端尚不支持，请用官方封装编辑器"，并在 README 功能表标 🔴。

**验收**：V4 用户点击后能明确知道"这不是我装错了"，且知道替代路径。

### P1 · 发布前 1 周内应完成（约 3 天）

#### 7.4 README / 内置帮助的 V4 矩阵

**证据**：README 功能表 22 行**全部**写 "V2.2/V3"，`about/features.js` 的 `version` 字段同样；
安装说明只有 V2.2 与 V3 两条路径，**没有 V4**；`extension.json` 的 `engines.eda` 仍是 `^2.2.45`。

**要做**：功能表加一列 V4 实测状态（✅ / ⚠️ / ❌），补 V4 安装步骤，`engines` 明确写成兼容范围。

**验收**：一个没用过插件的 V4 用户，只看 README 能在 5 分钟内装上并跑通第一个功能。

#### 7.5 隐私与数据说明

**证据**：`工作时间统计` 后台记录使用时长与工程耗时（`sys_Storage` 本地），`批量替换器件` 会向立创商城 API 查询器件参数。
README 只有免责声明，没有"采集什么 / 存哪里 / 是否上传"。

**要做**：加一节说明——工时数据**纯本地**、可用"导出全部数据为 JSON"带走、卸载即清；
联网请求只发生在批量替换/取库时，域名与用途写清楚。

**验收**：扩展市场审核能直接引用该节；用户能据此判断是否可接受。

#### 7.6 CI：把已经写好的门禁挂到远端

**证据**：`.github` 不存在；`npm test`（含 `pretest` 的两道门禁）+ `test:samples` + `build` 本地跑一遍约 **30 秒**。

**要做**：GitHub Actions 三步——`npm ci` → `npm test && npm run test:samples` → `npm run build` 并上传 `.eext` 产物；
`test/pages/run.mjs`（需 Chrome）放 nightly。

**验收**：任何 PR 不绿不能合；tag 推送自动出包，版本号与 `extension.json` 不一致时构建失败。

#### 7.7 覆盖率基线

**证据**：无 `c8`/`nyc`，无法回答"改了这块会不会踩到"。

**要做**：`c8 node --test`，先只统计 `iframe/js/src/**` 与 `src/js/**`，把当前数字记为基线，只允许升。

**验收**：能一眼看出"这次改动碰到了哪块没测的地方"。
