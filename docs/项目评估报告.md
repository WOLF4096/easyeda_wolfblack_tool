# 狼黑工具（WolfBlack Tool）项目评估报告

> 评估对象：`pro-api-sdk`（嘉立创EDA / EasyEDA 专业版扩展插件）  
> 评估时间：2026-10-20  
> 评估维度：架构设计 · 代码质量 · 可维护性 · 性能 · 安全 · 依赖管理 · 测试覆盖

---

## 一、项目概述

狼黑工具是一款面向嘉立创EDA专业版（EasyEDA Pro，V2.2 / V3 客户端）的辅助扩展插件，覆盖 20+ 个高频 PCB/原理图工作流功能，包括：

- **几何/格式转换**：焊盘⇄过孔、导线⇄线条、填充⇄图片、丝印代码转换（E96 阻值）
- **数据导入导出**：导入图片/二维码/BOM/AD 网表，导出引脚网络/周报
- **网表与网络**：生成物理网络（纯空间几何算法）、批量修改网络、刷新网表
- **器件管理**：位号查重、批量替换器件、模型批量更新、创建封装、从 PCB 转原理图
- **工程辅助**：工作时间统计、基准测试（API 坐标校准）、EDA 桥

**技术栈**：TypeScript（入口）+ JavaScript（核心逻辑）、esbuild 打包（IIFE + tree-shaking）、ESLint(Alloy) + Prettier + Husky + lint-staged、iframe 承载前端 UI。宿主交互完全依赖嘉立创 EDA 的 `eda.*` API（`eda.sys_*` / `eda.pcb_*` / `eda.sch_*` / `eda.dmt_*`）。

**规模概览**：

| 指标         | 数值                                                           |
| :----------- | :------------------------------------------------------------- |
| 入口 TS      | 1 个（`src/index.ts`，244 行）                                 |
| 核心逻辑 JS  | 7 个（约 2,214 行）                                            |
| 前端 HTML    | 18 个（约 17,472 行，其中 6 个 > 1000 行）                     |
| 本地第三方库 | 6 个（echarts / jspdf / jszip / bwip-js / crypto-js / fflate） |
| 依赖规模     | 308 个包（全部 devDependencies），node_modules 97MB            |
| 测试文件     | 0 个                                                           |
| CI/CD        | 无（无 `.github` 目录）                                        |

## 二、优点

1. **功能价值高、真实解决痛点**：功能覆盖面广，且大多源于真实 PCB 设计工作流（如"从 PCB 转原理图""生成物理网络"），而非造轮子。
2. **工程规范意识好**：配置了 ESLint（Alloy + tsdoc 插件）、Prettier（含 import 排序）、Husky + lint-staged 提交钩子，`strict` + 全套 strict 家族编译选项开启。
3. **构建方案现代**：使用 esbuild 打包（tree-shaking + IIFE），相比传统 webpack 轻量高效；采用动态 `import()` 实现按需懒加载，主入口保持精简。
4. **版本兼容处理细致**：针对 V2.2 / V3 两代客户端的 API 差异做了大量适配，并通过"基准测试"用本地校准参数动态适配坐标/尺寸漂移，替代硬编码版本判断（`PadViaConverter` / `WireConverter` 已落地该思路）。
5. **文档与发布规范**：README 功能表、安装说明、免责声明、CHANGELOG 更新日志齐全，每个功能附使用说明链接，面向用户的免责与数据风险提示到位。
6. **有明确的性能优化意识**：如"从 PCB 创建导线"弃用 API 逐条创建、改为源码批量写入，1000 条导线性能提升 20 倍；压缩打包开启 DEFLATE level 9。

## 三、问题清单

### 3.1 架构设计（中等）

|  #  | 问题                                | 说明                                                                                                                                                                        |
| :-: | :---------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | **TS 入口 + JS 逻辑混用，类型缺失** | 项目名义是 TypeScript，但核心逻辑全部是纯 JS（`allowJs: true`），仅靠 JSDoc 注释，类型安全收益几乎为零，`eda.*` API 全靠隐式全局 `any`。                                    |
| A2  | **单体 HTML 巨型文件**              | `WorkingHours.html`（2766 行/153KB）、`GenerateNet.html`（2072 行）、`PcbToSch.html`（1664 行）等，内联 CSS+JS+HTML 混在一起，无组件化/模块化，可维护性差。                 |
| A3  | **重复代码**                        | `WireConverter` 与 `RegionImageConverter` 的 path 解析、贝塞尔降级逻辑高度重复；V2/V3 版本判断散落各文件（`currentVersion.startsWith('2.')`）。                             |
| A4  | **死代码 / 悬空引用**               | `src/index.ts` 中 `NetReplace()` 打开不存在的 `/iframe/NetReplace.html`（实际文件为 `ModifyNet.html`）；大量注释掉的旧实现（PadToVia、ImportGerber、ExportFile 等）未清理。 |

### 3.2 代码质量 / 可维护性（偏低）

|  #  | 问题                       | 说明                                                                                                                                              |
| :-: | :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| C1  | **调试日志大量残留**       | `AutoWirePlacer.js` 37 处 `console.*`、`ReplaceComponent.html` 28 处，多处 `console.log(curDoc)` 等原始对象打印，生产环境未清理。                 |
| C2  | **魔法数字硬编码**         | 图层号（`layer === 12` 通孔、`1/2/15~46` 铜层）、角度、`-1000` 阻焊默认值等散落，无常量/枚举语义化。                                              |
| C3  | **国际化（i18n）形同虚设** | 代码内大量硬编码中文，`locales/` 仅有 `About` 一个词条，中英文界面文案无法真正切换。                                                              |
| C4  | **命名不一致**             | `PcbToSch`（HTML 文件名）vs 各 `registerFn` 混用大小写；`fishBuffer`/`摸鱼` 等内部命名偏口语化。                                                  |
| C5  | **错误处理粗糙**           | 大量空 `catch(e) {}` 吞异常（`WorkingHours.js` 多处），用户无感知；`AutoWirePlacer` 切换页面逻辑存在 `_lastSchematicTabId` 可能为 `null` 的隐患。 |

### 3.3 性能（中等）

|  #  | 问题                        | 说明                                                                                                                                                              |
| :-: | :-------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | **反调试死循环（严重）**    | `WorkingHours.html:1888` 存在 `setInterval(() => { Function('debugger')(); }, 200)`，每 200ms 触发一次 debugger，持续占用主线程，属严重性能隐患与恶意反调试行为。 |
| P2  | **逐条 API 调用未批量化**   | `WireConverter` / `PadViaConverter` 转换时对每个图元 `await` 逐个调用 create/delete，图元多时往返开销大。                                                         |
| P3  | **第三方库全量引入**        | echarts（1.5MB）、jspdf（549KB）等按需未裁剪，前端首次加载体积大。                                                                                                |
| P4  | **全量源码读取 + 正则扫描** | `getDocumentSource()` 全量读取文档，再用正则全局扫描提取 `maxId`/`maxTicket`，大工程下为 O(n) 且重复遍历。                                                        |

### 3.4 安全（偏低）

|  #  | 问题                          | 说明                                                                                                                                                           |
| :-: | :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | **"假加密"导出**              | `WorkingHours.html` 的"安全导出"生成独立 HTML，AES-GCM 密钥（`k`）连同密文（`ct`）一起明文内嵌于 HTML，拿到文件即可解密——本质是"安全靠混淆"，无实际保密性。    |
| S2  | **反调试 + 控制台禁用**       | 覆盖 `window.console`、拦截 F12/Ctrl+U、无限 `debugger`，对合法用户调试不友好，属"防君子不防小人"的反模式，且涉嫌过度防御。                                    |
| S3  | **CDN 依赖（供应链 + 隐私）** | `ImportQrcode.html` 等引用 `cdn.jsdelivr.net` 的 echarts/fflate，本地工具却依赖公网 CDN：离线失效 + 存在投毒风险，且与本地 `iframe/js/` 内置版本并存、不一致。 |
| S4  | **innerHTML 使用面广**        | 全项目 54 处 `innerHTML`（WorkingHours 20 处），虽有部分 `escapeHtml`，但需逐处审计是否存在未转义的用户输入拼接（XSS 面）。                                    |

### 3.5 依赖管理（中等偏上）

|  #  | 问题                     | 说明                                                                                                        |
| :-: | :----------------------- | :---------------------------------------------------------------------------------------------------------- |
| D1  | **版本号不一致**         | `package.json` 为 `1.1.1`，`extension.json` 为 `1.16.0`，CHANGELOG 已到 `v1.16.0`，三处未对齐，易误导发布。 |
| D2  | **无依赖安全审计**       | 无 `npm audit` 脚本、无 lockfile 更新机制，308 个传递依赖无漏洞巡检。                                       |
| D3  | **无运行时依赖（合理）** | 全部依赖为 devDependencies，符合浏览器打包扩展的定位，此为正确做法。                                        |

### 3.6 测试与 CI（严重缺失）

|  #  | 问题             | 说明                                                                                                                          |
| :-: | :--------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| T1  | **零自动化测试** | 无任何 test/spec 文件、无测试框架、无 coverage 配置。核心几何算法（物理网络、贝塞尔降级、仿射变换）无回归保障，仅靠手工验证。 |
| T2  | **无 CI/CD**     | 无 GitHub Actions 等流水线，构建/打包/发布全本地手动，提交仅依赖 pre-commit 钩子做 lint。                                     |

## 四、改进建议（按优先级）

### P0 — 立即处理（安全 / 性能红线）

1. **移除反调试死循环**（`WorkingHours.html:1888`）：删除 `setInterval(Function('debugger'), 200)`，以及控制台禁用、F12 拦截逻辑；确有防篡改诉求时改用只读水印或服务端签名校验，而非阻塞式 debugger。
2. **修正"假加密"**：若需保护导出数据，密钥不可随密文下发，改用服务端/用户口令派生（PBKDF2），或直接去掉加密、明确标注"明文可读"。
3. **统一第三方库来源**：CDN 与本地二选一，优先本地打包，消除供应链与离线风险。
4. **修复悬空引用**：删除 `NetReplace()` 死函数或补全 `NetReplace.html`，统一 `registerFn` 命名。

### P1 — 短期改进（可维护性）

1. **清理残留调试日志**：删除或收敛到统一 logger（带开关），生产构建剥离 `console.*`。
2. **常量化魔法数字**：图层号、铜层区间、阻焊默认值等提取为语义化枚举/常量模块。
3. **消除重复代码**：抽取 path 解析、贝塞尔降级、V2/V3 格式判断为共享工具函数。
4. **补齐错误处理**：空 `catch` 至少记录日志并给出用户可感知提示；`_lastSchematicTabId` 判空。

### P2 — 中期改进（架构演进）

1. **前端组件化**：拆分巨型 HTML，引入模块化（CSS/JS 分离，或迁移到轻量框架 + 构建），降低单文件复杂度。
2. **核心逻辑迁移 TypeScript**：为 `eda.*` API 建立 `.d.ts` 类型声明（`@jlceda/pro-api-types` 已具备），让 `strict` 真正生效。
3. **批量操作批量化**：图元转换类功能支持批量 create/delete（若宿主 API 支持），或至少并行化 Promise。
4. **对齐版本号**：建立单一版本源（如 `package.json` 驱动 `extension.json` 与 CHANGELOG）。

### P3 — 长期改进（工程化闭环）

1. **建立测试体系**：为核心几何/解析算法（物理网络、路径转换、网表解析）编写单元测试，目标覆盖核心模块 ≥ 60%。
2. **接入 CI/CD**：GitHub Actions 实现 lint + build + test 自动流水线，自动生成 `.eext` 产物。
3. **依赖治理**：定期 `npm audit`、锁文件升级、依赖最小化；考虑 `npm ci` 固化安装。

## 五、评分结论

### 分维度评分（百分制）

| 维度                | 权重 | 得分 | 简评                                                          |
| :------------------ | :--: | :--: | :------------------------------------------------------------ |
| 架构设计            | 25%  |  62  | 动态加载+模块拆分合理，但 TS/JS 混用、单体 HTML、重复代码拖累 |
| 代码质量 / 可维护性 | 25%  |  55  | 日志残留、魔法数字、死代码、i18n 缺失                         |
| 性能                | 15%  |  60  | 有批量源码写入的亮点优化，但反调试死循环、逐条 API 调用抵消   |
| 安全                | 15%  |  55  | 假加密、CDN 供应链、innerHTML、反调试反模式                   |
| 依赖管理            | 10%  |  68  | 无 runtime 依赖正确、esbuild 现代，但版本号不一致、无审计     |
| 测试覆盖            | 10%  |  20  | 零测试、无 CI，核心算法无回归保障                             |

### 综合评分：**55 / 100（中等偏下）**

**结论**：这是一款**功能价值高、工程化成熟度不足**的工具型项目。它真实解决了 PCB 设计中的大量痛点，文档、发布与构建意识良好，性能上也有"源码批量写入"等可圈可点的优化；但在代码可维护性（单体 HTML、日志残留、魔法数字）、安全（假加密、反调试、CDN）、以及测试/CI 三方面存在明显短板。建议优先处理 P0 的 4 项安全/性能红线，再逐步推进组件化、类型化与测试体系建设，项目即可从"好用的小工具"进阶为"可靠的产品"。
