## 一、结论摘要

| 项目 | 结果 |
| :--- | :--- |
| **综合评分** | **66 / 100**（上一版 55，**+11**） |
| **分功能平均分** | **74 / 100**（27 个功能） |
| 最高分功能 | 焊盘⇄过孔 87、导线⇄线条 86、从 PCB 创建导线 84 |
| 最低分功能 | 批量替换器件 57、创建封装 62、工作时间统计（前端）64 |
| 测试 | 58 个用例全绿，覆盖 4 个模块（上一版 0） |

**一句话结论**：单个功能的完成度已经不错（平均 74 分），但**跨功能的工程基建仍在拖后腿**（综合 66 分）——586 KB 死资源随包分发、201 处 `console`、24 处空 `catch`、零 CI、类型仍是纯 JS。下一步的收益不在"再做一个功能"，而在"把已有 27 个功能的运维成本降下来"。

**投入产出最高的 3 件事**（合计约半天）：

1. 删 `jspdf.umd.min.js` + `crypto-js.min.js`（**两个库全仓 0 引用**）：解包 -586 KB，压缩后 -151 KB，`.eext` 直接瘦身约 **13%**；
2. 在 `common.js` 里缓存版本号（当前 `GenerateNet` 逐行调用宿主 API，是本次重构引入的性能回归）；
3. 清掉 `NetReplace()` 死导出 + 把 `AutoWirePlacerNET` 注册进菜单（现在用户在菜单里点不到这个功能）。

## 四、剩余问题清单（按优先级）

### P0 — 立即处理（低成本、确定收益）

**P0-1 · 版本号在循环里被反复查询（本次重构引入的性能回归）**
`GenerateNet.js:1375` 的 `for (let line of lines)` 循环内，`:1383` / `:1412` 每行都调用 `isV2()` / `isV3()`；而 `common.js` 的 `getEditorVersion()` 每次都穿透到宿主 `eda.sys_Environment.getEditorCurrentVersion()`。一个上万行的 PCB 源码就是上万次跨 iframe 调用。
> **改法**：`common.js` 内做一次性缓存（`let _ver; getEditorVersion(){ return _ver ??= 读一次 }`），或在循环外先取 `const v3 = isV3()`。改动 < 5 行。

**P0-2 · 两个第三方库完全没被引用，却在随包分发**
`iframe/js/jspdf.umd.min.js`（**536 KB**）与 `iframe/js/crypto-js.min.js`（**50 KB**）：全仓（HTML/JS/TS）除文件自身外 **0 处引用**，无任何页面 `<script>` 加载。
> **收益**：解包 -586 KB；按 DEFLATE level 9 实测（jspdf 536→134 KB、crypto-js 50→17 KB），`.eext` 由 1.16 MB 降至约 **1.01 MB（-13%）**。直接删除即可，无代码改动。

**P0-3 · 悬空导出 `NetReplace()`**
`src/index.ts:100` 打开 `/iframe/NetReplace.html`，该文件不存在（真实功能是 `ModifyNet`）。目前没挂在菜单上，所以用户点不到，但只要有人在菜单里补一项就会踩坑。
> **改法**：删除该导出（`ModifyNet` 已有独立菜单项）。

**P0-4 · `AutoWirePlacerNET` 已导出但没注册进菜单**
`src/index.ts:30` 定义了"从网表文件导入放线"，但 `extension.json` 的 23 个 `registerFn` 里没有它 → **用户无法触达**（从 PCB 取数那条 `AutoWirePlacerPCB` 有菜单）。
> **改法**：要么在"从 PCB 创建导线"下补一个子项，要么删掉该导出，避免"看起来有、实际没有"。

### P1 — 短期改进（1~2 天）

**P1-1 · 201 处 `console.*` 没有统一出口**
分布：`ReplaceComponent.js` 36、`PcbToSch.js` 17、`CreateFootprint.js` 11、`GenerateNet.js` 10、`ImportBom.js` 8，另有 `console.log(jsonData)` 这类整对象打印。
> **改法**：`common.js` 增加 `logger`（`debug/info/warn/error` + 开关），生产构建剥离 `debug`；优先处理 Top3 文件。

**P1-2 · 24 处空 `catch {}` 静默吞异常**
分布：`GenerateNet.js` 7、`ReplaceComponent.js` 5、`EDABridge.js` 4、`WorkingHours` 5（前端 2 + 后端 3）、`CreateFootprint.js` 2、`src/index.ts` 1。
其中 `EDABridge` 220 行里有 4 处，属于"整块功能失败但界面无提示"。
> **改法**：至少 `logger.warn(err)`；用户可感知的路径补 `sys_Message.showToastMessage`。

**P1-3 · `escapeHtml` 有 4 份实现，其中一份不完整**
`InADNetlist.js:221`（完整）、`WorkingHours.js:45`（完整）、`WorkingHours.js:1296`（导出模板内又一份）、`PcbToSch.js:712`（**只转义双引号**，`&`/`<`/`>` 未转义，且正文内容完全未转义）。
> **改法**：抽到 `common.js` 的 `escapeHtml`，删除 3 份副本；`PcbToSch` 的 `title="${...}"` 与正文 `${...}` 都要转义。这是可验证的 XSS/渲染缺陷面（当前数据源是用户自己的工程，风险等级中低）。

**P1-4 · 7 处 `alert()` 与宿主 UI 不一致**
`OutPinNet` 4 处、`NetlistUpdate3DModels` 2 处、`ClearEmptyProperties` 1 处；其它页面统一用 `eda.sys_Message.showToastMessage`。
> **改法**：统一换成 toast，`alert` 会阻塞 iframe 且样式与 EDA 主题割裂。

**P1-5 · 魔法数字未语义化**
`layer === 12`（通孔层）、`layer === 1 || 2 || 15~46`（铜层，见 `WireConverter.js:102`）、阻焊默认 `-1000`（6 处）、`WIRE_LENGTH = 40`。
> **改法**：`src/js/common/pcbConstants.js` 导出 `LAYER.SMD/THT/COPPER_RANGE`、`MASK.DEFAULT_EXPANSION`。

**P1-6 · `common.js` 是 18 个页面的硬依赖，缺一即白屏**
所有页面都在顶层 `const { ... } = window.WolfCommon;`，若 `common.js` 未加载（旧缓存、路径变更），会直接 `TypeError: Cannot destructure property ... of undefined`，整页脚本停摆且无任何提示。
> **改法**：`const WC = window.WolfCommon || {};` + 显式提示"公共模块加载失败"。

### P2 — 中期改进（架构层面）

**P2-1 · 仍有两个"千行级"前端脚本**
`WorkingHours.js` 2,165 / `GenerateNet.js` 1,664 / `PcbToSch.js` 1,459 / `ReplaceComponent.js` 1,021，占前端脚本总量 **59%**。
> **改法**：按"数据层 / 渲染层 / 导出层"再切一刀（`GenerateNet` 已有 `parseV2Primitives` / `parseV3Primitives` 可独立成文件）。

**P2-2 · V2/V3 源码发射逻辑存在两份实现**
`PcbToSch.js` 与 `src/js/autoWire/index.js` **各写了一份** `["WIRE",...]`（V2）与 `{"type":"WIRE",...}`（V3）的源码拼装。两边对 `maxId`/`ticket`/末尾 `|` 的处理规则一旦漂移，就会出现"某版本写不进去"的隐蔽 bug。
> **改法**：把"源码 schema"抽成共享常量/函数（后端一份，前端通过 `iframe/js/common.js` 复用同构实现），并补参数契约测试。

**P2-3 · 导出报告依赖公网 CDN**
`WorkingHours.js:1229-1230` 生成的导出 HTML 从 `cdn.jsdelivr.net` 加载 echarts 与 fflate → **离线环境下导出的报告图表全空**，且与本地 `iframe/js/` 内置版本并存（版本可能漂移）。
> **改法**：导出时把库内联（体积换可用性），或把图表降级为纯 SVG/表格。

**P2-4 · 59 处 `innerHTML`，未见统一转义策略**
`WorkingHours.js` 20 处、`ImportBom.js` 6 处、`GenerateNet.js` 6 处为主要分布。
> **改法**：先审计"拼接了外部/工程数据"的十几处（设计ator、器件名、网表名都来自用户的工程文件），其余保持。

**P2-5 · i18n 骨架是空壳**
`locales/zh-Hans.json` 与 `en.json` 各 2 个词条，`locales/extensionJson/` 是空目录；前端硬编码中文约 21,000 字。要么补齐，要么删掉骨架避免误导。

**P2-6 · 版本号仍是"两处手改"**
`package.json` 与 `extension.json` 靠人肉同步（历史上就翻过车，见上版 D1）。
> **改法**：`build/packaged.ts` 打包前用 `package.json.version` 覆写 `extension.json`。

| 依赖管理 | 10% | 68 | **70** | +2 | 版本号已对齐、无 runtime 依赖；但 2 个零引用库 586 KB、无 audit、`build/dist` 78 MB 入库 |
| 测试覆盖 | 10% | 20 | **45** | +25 | 58 用例 + 参数契约测试（最有价值的一类）；但只覆盖 4 个模块、前端 0 覆盖、无覆盖率统计、无 CI |

**综合分计算**

```
70×0.25 + 66×0.25 + 68×0.15 + 66×0.15 + 70×0.10 + 45×0.10
= 17.5 + 16.5 + 10.2 + 9.9 + 7.0 + 4.5
= 65.6  →  66 / 100
```

**结论**：从 55 → 66，是"还技术债"带来的真实提升——但这轮基本只借到了"去重 + 测试从 0 到 1"的分。**剩下 34 分几乎全在工程基建上**：CI、类型、日志、死资源、产物治理。按 P0 → P1 的顺序推，预计下一次能到 75 分区间；要到 85+ 必须动 P2-1（千行文件拆分）与 P3-2（类型化）。
