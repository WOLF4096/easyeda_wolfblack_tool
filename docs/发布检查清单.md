# 发布检查清单

> 每次对外发版逐项勾选。带 ⚠️ 的是「漏了会出事」的项。

## 一、代码与测试

- [ ] `npm test` 全绿（`pretest` 自动跑 `check:deps` + `check:js`，两者必须 0 违规）
- [ ] `npm run test:samples` 10/10 用例、3/3 样本通过
- [ ] `npm run build:iframe` 无报错，18 页全部产出
- [ ] `npm run check:layout` 18 页 0 溢出
- [ ] `node test/pages/run.mjs` 不新增失败（`WorkingHours` 的 canvas 0 尺寸告警是 mock 缺口，非回归）
- [ ] ⚠️ 改过写盘路径的话：`docs/V4回归记录.md` 已追加本轮的验证记录

## 二、版本与元数据

- [ ] `package.json` 的 `version` 已更新
- [ ] `extension.json` 的 `version` 已更新（**平台读这个**，漏改会导致装上去还是旧版）
- [ ] 两者一致（`test/docConsistency.test.mjs` 会核对）
- [ ] `CHANGELOG.dev.md` 已加技术段落
- [ ] `CHANGELOG.md` 已加用户向段落（新增 / 修复 / 优化 / 移除）
- [ ] 「关于」页显示的版本号正确（构建期从 `package.json` 注入，无需手改，但要重新 `build:iframe`）
- [ ] `extension.json` 的 `keywords` / `categories` 与新功能匹配

## 三、文档

- [ ] README 功能表与 `features.js` 逐条一致（`npm test` 会核对）
- [ ] 新增功能在 README 有「怎么用」小节
- [ ] 新增功能在「关于」页有步骤与注意事项
- [ ] ⚠️ 有破坏性行为变化时，README「常见问题」与 About 的提示已同步
- [ ] `PRIVACY.md` 与实际行为一致（新增联网动作时尤其要改）

## 四、出包

- [ ] `npm run build` 成功
- [ ] `build/dist/wolfblack-tool_v<版本>.eext` 存在
- [ ] 包体积无明显异常（当前约 1.43 MB；工时页内嵌图表库占 679 KB）
- [ ] 包内不含 `test/`、`测试样本/`、`tools/`（`.edaignore` 已排除）
- [ ] 包内 grep 不到 `cdn.jsdelivr.net`

## 五、装包实机验证（干净环境）

- [ ] 在**未装过**插件的 EDA 上导入新包
- [ ] 扩展管理器里勾选「允许外部交互」「显示在顶部菜单」后能看到菜单
- [ ] 打开 3 个代表页面：导入图片、生成物理网络、工作时间统计
- [ ] 「关于」页能展开功能详情，版本号正确
- [ ] 卸载后重装，配置与工时记录仍在（本地存储未被清）

## 六、商店资料

- [ ] 标题、简介、详情来自 `docs/商店文案.md`，且与 README 口径一致
- [ ] 截图已更新（至少：功能列表页、两三个典型功能操作中、工时图表）
- [ ] 更新说明（本版新增/修复）已填
- [ ] 分类与关键词已确认

## 七、回滚预案

- [ ] ⚠️ 上一版的 `.eext` 已留存（`build/dist/` 里不要只保留新包）
- [ ] 在 `CHANGELOG.md` 里能一眼看出本版改了哪些用户可见行为
- [ ] 若本版有问题，能说清降级步骤：扩展管理器卸载 → 导入上一版 `.eext` → 重新勾选配置项

## 八、发版后

- [ ] GitHub 打 tag（`v<版本>`）并附本版 CHANGELOG 段落
- [ ] 扩展广场的更新说明已发布
- [ ] 记录一条：本版有无用户反馈的回归问题（有则开 issue 跟踪）
