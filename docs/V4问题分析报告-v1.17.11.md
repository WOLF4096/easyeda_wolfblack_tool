# V4 专项问题分析报告（v1.17.11）

> 测试环境：嘉立创 EDA 专业版 **V4.1.78**（通过「EDA 桥」实连，`127.0.0.1:4178`，桥页面勾选「调试指令」）
> 对照环境：同一工程的 V3 源码样本（`测试样本/Board_V3.2.149.epro2`）、V4 样本（`测试样本/ProDoc_V4.1.78.epro2`）
> 结论全部来自**实机复现 + API 实测**，不是纯代码推断；每条都写明"怎么验证的"。

---

## 0. 结论速览

| # | 功能 | V4 现象 | 根因（一句话） |
|---|---|---|---|
| 1 | 批量替换器件 | 报「未能在库中找到对应的器件」 | `lib_Device.getByLcscIds(单个编号)` 在 V4 返回**对象**而不是数组，`t.length > 0` 恒为 false |
| 2 | 图片 ⇄ 填充 | 报「无法创建填充图元」 | 图像的 `path` 是**子路径数组**，`createPolygon()` 只吃**单条扁平路径**，返回 `undefined` |
| 3 | 批量替换网络 | 大小写不同就匹配不上 | 匹配用的是 `Map` 精确键，未做大小写归一 |
| 4 | PCB 转原理图 | 导线在、**符号全丢** | 生成的 COMPONENT 行**缺 `attrs`**，V4 会**静默丢弃**该器件（写入仍返回 true） |

## 1. 批量替换器件：V4 报「未能在库中找到对应的器件」

### 1.1 复现

画布上只有一个 `R1`（器件 `Res_0603` / 封装 `R0603`），粘贴规则 `R1 → C53954311`，点「获取数据」。

### 1.2 实测证据

```js
// 在 V4.1.78 实机执行
const t = await eda.lib_Device.getByLcscIds('C53954311');
Object.prototype.toString.call(t)   // → "[object Object]"   ← 单个器件对象，不是数组
t.length                            // → undefined
```

返回对象里字段齐全（`uuid` / `libraryUuid` / `name` / `footprint` / `otherProperty` …），**数据本身没问题，是形态变了**。

而 `@jlceda/pro-api-types@0.1.175` 的声明是：

```ts
getByLcscIds<T extends boolean>(lcscIds: string, libraryUuid?: string, allowMultiMatch?: T)
  : Promise<T extends true ? ILIB_DeviceSearchItem | undefined : Array<ILIB_DeviceSearchItem>>;
```

→ 类型声明说"单编号返回数组"，**V4.1.78 运行时返回单个对象**（传数组才返回数组）。

### 1.3 为什么表现为"未能在库中找到器件"

`ReplaceComponent.js` 阶段 0：

```js
const t = await eda.lib_Device.getByLcscIds(supplierId);
if (t && t.length > 0) { ...placeCount++ }   // V4 下永远进不来
...
if (placeCount === 0) statusBar.setText("未能在库中找到对应的器件");
```

`length` 是 `undefined` → 分支被跳过 → `placeCount` 恒为 0 → 命中这句提示。**误导性的报错文案把真正原因藏住了。**

### 1.4 连带问题：V4 换了器件等于没换

修好取值后顺手实测了替换本身，发现 V4 器件引用有**两处**：

| 位置 | 字段 | 作用 |
|---|---|---|
| COMPONENT 行 | `attrs.DeviceName` = `{"name":"...","source":"","uuid":"..."}` | **权威引用** |
| ATTR 行 | `key:"Device"` 的 `value` | 只是上面的投影 |

实测（只改 ATTR `Device`）：EDA 会把新器件的属性、封装糊到器件上（`Manufacturer Part`、`Footprint` 都变了），但 `component.uuid` **仍是旧器件** → 器件没换，还留下"名称/封装与器件对不上"的脏状态。
**只改 COMPONENT `attrs.DeviceName` + ATTR `Device` 两处，`component.uuid` 才真正切换**（实测 R1 从 `Res_0603` 变成 `74LVC2G14GV_1`）。

### 1.5 还有一个 V4 专属的时序陷阱

V4 里**删除临时器件会连带销毁它带入文档的器件定义**：

```js
// 创建临时器件后文档里该器件 uuid 出现 2 次
s1.match(/26520808a9f621f9/g).length   // → 2
await eda.pcb_PrimitiveComponent.delete([pId]);
// 删完变成 0 次（160 行 → 源码里再也找不到这个器件）
```

旧流程是「读属性 → 删临时器件 → 写源码」，在 V4 下写进去的就是一个**不存在的器件 uuid**。
现在 V3/V4 改为「**先写源码、再删临时器件**」，并保留按 `(-10000,-10000)` 坐标兜底清理、关闭窗口时清理。

### 1.6 修复

`iframe/js/app/ReplaceComponent.js`

- 新增 `pickDevice()`（对象/数组归一）、`pickPrimitiveId()`（图元对象/数组/字符串归一）
- 新增 `getDeviceUuid()` / `getFootprintUuid()` / `getFootprintName()` / `getDeviceNameJson()`：V4 的 `component.uuid` 是对象，统一取里面的字符串
- `isModern()` 下延迟删除临时器件（`pendingTempIds` + `cleanupTempComponents()`）
- 顺带修掉 4 处 `catch (err) { logger.xxx(..., e) }` 引用未定义变量 `e` 的写法（会在 catch 里再抛 ReferenceError，把整个流程打断）

## 2. 图片 ⇄ 填充：V4 报「无法创建填充图元」

### 2.1 实测证据

在 V4 里创建一张 Image（矢量图标），读源码：

```json
{"type":"IMAGE", ... "path":[[-80,0.15,"L",-80,-41.5, ... ,-80,0.15]]}
```

`path` 是 **`Array<子路径>`**（外层数组 = 轮廓数，二维码就是几百上千个轮廓）。

依次调用（复现旧代码）：

```js
await eda.pcb_MathPolygon.createPolygon(data.path)   // → undefined（嵌套数组不合法）
await eda.pcb_PrimitiveFill.create(13, undefined, ...) // → 抛「无法创建填充图元，可能是传入的参数不正确。」
```

对照 API 声明：

```ts
createPolygon(polygon: TPCB_PolygonSourceArray)          // 单条扁平路径
createComplexPolygon(complexPolygon: TPCB_PolygonSourceArray | Array<TPCB_PolygonSourceArray> | ...)  // 支持多轮廓
```

实测 `createComplexPolygon(data.path)` → 正常返回；单轮廓、**5 个分离轮廓**（模拟二维码模块）都能建出填充。

### 2.2 修复

`src/js/RegionImageConverter.js`

- 填充改用 `createComplexPolygon()`（新增 `_toPolygon()`：优先复杂多边形，老版本退化为 `createPolygon(path[0])`）
- **填充图元的 `primitiveType` 在 V4 是 `Fill`，不是 `Region`** —— 旧过滤 `=== 'Region'` 把填充全漏掉了（选填充点转换"没反应"）
- 删除源图元改为按真实类型分派 `_deleteSource()`：`pcb_PrimitiveRegion.delete()` 删填充**返回 false 且不报错**，图元会留下
- `_extractPath()` 增加 `Array.isArray(data.path)` 校验：彩色图片（二进制内嵌对象）源码里 `path` 是 `blob:...` 字符串，不是路径数组

### 2.3 验证

| 场景 | 结果 |
|---|---|
| 单轮廓图片 → 填充 | 成功 |
| 5 个分离轮廓（二维码形状）→ 填充 | 成功（`createComplexPolygon` 正常） |
| 填充 → 图片（反向） | 成功 |

> 彩色图片 / 二维码彩色图（`primitiveType === 'Object'`，源码只有 `blob:` 地址、没有矢量路径）**无法直接转填充**，现在会明确提示，不再静默无反应。

## 3. 批量替换网络：大小写 + 转大写

### 3.1 改动

`iframe/js/app/ModifyNet.js` + `iframe/ModifyNet.html`

- 规则表 `replaceMap` 的键统一 `toLowerCase()`，匹配时把网表里的网络名也转小写 → **匹配不区分大小写**
- 「执行替换」按钮左侧新增 **`转大写` 复选框，默认勾选**；勾选时新网络名整体 `toUpperCase()`（中文/数字不受影响，只转英文字母）
- 输入区提示补了一句「旧网络名匹配不区分大小写」

### 3.2 行为说明

| 输入规则（Excel） | 网表里的网络名 | 勾选转大写 | 结果 |
|---|---|---|---|
| `vcc_3v3 → vcc3v3` | `VCC_3V3` | 是 | 换成 `VCC3V3` |
| `vcc_3v3 → vcc3v3` | `VCC_3V3` | 否 | 换成 `vcc3v3` |
| `net_a → net_b` | `Net_A` | 是 | 换成 `NET_B` |

## 4. PCB 转原理图：V4 导线在、符号全丢

### 4.1 复现与实测方法

在当前工程的原理图页（V4）上用 `setDocumentSource` 写入两种形态的 COMPONENT 行，观察 `sch_PrimitiveComponent.getAll()`：

| COMPONENT 行字段 | `setDocumentSource` 返回 | 实际生成器件 |
|---|---|---|
| `partId / x / y / rotation`（**旧代码的写法**） | `true`（假成功） | **0 个**（器件被静默丢弃） |
| 上面 + `zIndex` | `true` | **0 个** |
| 上面 + `isMirror` | `true` | **0 个** |
| 上面 + **`attrs`**（`Symbols`/`Devices`/`Footprints`/`DeviceName`/`FootprintName`/`pinClass`/`differentialPairClass`） | `true` | **1 个，符号正常绑定** |

结论：**V4 的 COMPONENT 行必须带 `attrs`**，否则写入"成功"、器件消失。导线（WIRE / LINE 行）本来就是完整形状，所以照旧显示 —— 正好就是「导线在、符号全丢」。

另外两条（同批实测）：

- ATTR 行**字段必须齐全**（`x/y/rotation/color/fontFamily/fontSize/fontWeight/italic/underline/align/value/keyVisible/valueVisible/key/fillColor/parentId/zIndex`）。只写 `parentId/key/value` 时整份源码直接拒写（返回 `false`）。
- 每个器件**必须有一条 `Channel ID` 属性**（空串即可）。去掉它，整份源码同样拒写。

对照 V4 真实源码（EDA 自己写的器件）：

```json
{"type":"COMPONENT", ...}||{"partId":"电阻.1","x":220,"y":110,"rotation":0,"isMirror":false,
  "attrs":{"Footprints":"[]","Devices":"[]","DeviceName":null,"FootprintName":null,
           "pinClass":{},"differentialPairClass":{},"Symbols":"[]"},"zIndex":13}|
```

### 4.2 修复

`iframe/js/app/PcbToSch.js`（现代格式分支，两个布局分支都改）

- 新增 `schComponentLine()`：COMPONENT 行带 `isMirror` + `attrs` + `zIndex`
- 新增 `schAttrLine()`：ATTR 行输出**完整 17 个字段**
- 每个器件补 `Channel ID` / `Group ID` / `Reuse Block`（与 EDA 自身写盘一致）
- 位号 / 名称的 ATTR 带 `valueVisible: true`，其余保持 `null`（跟真实源码一致）

### 4.3 写入自检（防"假成功"）

`setDocumentSource` 在 V4 可能返回 `true` 但不生成任何器件。现在写入后会真的清点一次：

```js
const comps = await eda.sch_PrimitiveComponent.getAll();
if (isSuccess && comps.length === 0) → 提示「源码已写入，但器件没有生成：原理图页可能有旧内容，建议新建一个空白原理图页后重新写入」
```

> 实测中，往一个**已有内容**的原理图页整份写入时，V4 对 id/占位较敏感（同样的行在"只有 1 个器件"的页面上能落地，混入更多改动时容易整份拒写）。因此建议：**转图前先新建一个空白原理图页**，这也是自检提示里那句话的由来。

## 5. V4 与 V3/V2 的关键差异（本次新增认知）

| 项 | V2.2 | V3 | V4 |
|---|---|---|---|
| `lib_Device.getByLcscIds(单编号)` | 数组 | 数组 | **单个对象** |
| `component.uuid` | 字符串 | 字符串 | **对象** `{name,source,uuid}` |
| 器件引用权威字段 | ATTR `Device` | ATTR `Device` | **COMPONENT `attrs.DeviceName`** + ATTR `Device` |
| 删除器件是否连带删器件定义 | 否 | 否 | **是** |
| 填充图元 `primitiveType` | `Region` | `Region` | **`Fill`** |
| `pcb_PrimitiveImage.getAll()` | 只含 Image | 只含 Image | **会带上 Object 图元**（对其调用 `delete` 会抛 TypeError） |
| 多轮廓路径 | `createPolygon` 可接受嵌套 | 同 V2 | **只接受 `createComplexPolygon`** |
| SCH COMPONENT 行 | 数组格式 | 日志格式，`attrs` 可省 | **必须带 `attrs`** |
