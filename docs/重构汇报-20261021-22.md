## 三、这两天做了什么

### 3.1 10-21：V4 兼容性攻坚（v1.17.4 → v1.17.11）

EDA V4 与旧版 V2.2 在同一批 API 上有大量行为差异，插件此前按 V2.2 写。逐个实测定位：

| 现象 | 真实根因 |
|---|---|
| 导入图片/二维码报「宽度必须为正数」 | 把 `toFixed()` 的**字符串**当长度传给 API，V4 严格校验；报错文案误导成"值越界" |
| 批量替换器件 V4 报「未能在库中找到器件」 | `getByLcscIds()` 声明返回数组，**V4 实际返回对象**，`t.length > 0` 恒假 |
| 批量替换后「属性糊上了但器件没换」 | 器件引用有**两处**（COMPONENT 行 `attrs.DeviceName` + ATTR `Device`），只改后一处 |
| 替换后目标器件 uuid 失效 | V4 删临时器件会**连带销毁器件定义** → 必须先写源码、后删临时件 |
| 图片转填充「无法创建填充图元」 | 图像路径是**子路径数组**，必须用 `createComplexPolygon`，`createPolygon` 返回 `undefined` |
| 填充转图片删不掉源图元 | V4 填充的 `primitiveType` 是 **`Fill`** 不是 `Region`；`Region.delete()` 删填充返回 false 却不报错 |
| 从 PCB 转原理图「导线在、符号全丢」 | COMPONENT 行缺 `attrs`（7 个键）时 `setDocumentSource` **返回 true 但静默丢弃器件** |
| 13 个页面缺 `common.js` 时整页白屏 | 顶层解构前没判空，直接 `TypeError` |

同批还做了：统一日志出口（`console.*` 203 → 134）、21 处空 `catch` 补处理、7 处 `alert` 改 toast、恢复圆弧角度校准、源码发射器前后端合一并加**逐字节一致性测试**。

### 3.2 10-22 上午：样式与版式统一（v1.18.0）

- 18 个页面移除 `<style>` 与 `style=""`，样式收敛到 `iframe/css/common.css` 一个文件

- 新增 `npm run check:layout`：headless Chrome 按真实窗口尺寸逐页实测溢出/裁切，18 页 0 溢出

## 七、可复用的五条经验

1. **先测平台能力，再定架构**。宿主不支持原生 ESM 这件事，如果先拆完 18 个页面再发现，返工量是整个工程。
2. **写盘类重构不能只靠"看起来一样"**。字节对照抓到的那处 `FONTSTYLE` 参数错列，冒烟和肉眼都发现不了，写出去就是坏库。
3. **门禁要能自动增量**。基线文件而不是"下次一起清"，让复杂度约束随时间只降不升；基线键不含行号，改一行不会作废。
4. **测试要盯"口径"而不是"覆盖率"**。`25.4mm = 1000mil` 往返、`DQ6` 排在 `DQ10` 前、4 位编码规则只对电阻成立 —— 这些是改错之后完全看不出来的地方。
5. **注释格式要变成可执行契约**。模块头五个标签由测试核对 `@//exports/` 与真实导出，注释就不可能和代码脱节。
